# Flynn-AI — паттерны промпта для Fizika

Подмножество b24u-промпт-паттернов с поправками под Flynn-runtime. Базовая библиотека: `old/artifacts/b24u-current-state/prompt-patterns-library.md` — там полные формулировки. Здесь только что взять, что адаптировать и что появилось нового.

## 0. Иерархия источников (Flynn-специфика)

В Flynn-системном промпте уже работает типизация источников через теги. Подтверждено сегодняшним прогоном (8/10 PASS):

```
1. <OFFER id="…"> — фид-данные (площадь, цена, этаж, URL, планировка). Источник истины для конкретных лотов.
2. <CATALOG_CARD type="faq|text|site_page"> — ручные KB-записи. Slice-каталоги, FAQ, продуктовые описания.
3. Системный промпт (правила и тон).
4. Дефолтные сообщения — ТОЛЬКО когда в RAG 0 карточек ВСЕХ типов. Не раньше.
```

Сегодняшний баг C2 («сколько двушек Моисеенко с чистовой») = пункт 4 срабатывает раньше пункта 2, хотя в фиде есть live-карточки. **Лечится на стороне дашборда**, см. `flynn-dashboard-checklist.md`.

---

## 1. Подтверждённо работающие на Flynn (брать как есть из b24u-library)

- `<role>` — без изменений.
- `<output_format>` — формат строки лота работает. Бот выдаёт «{тип} {м²}, ЖК {название}, {эт} эт, {цена} млн ₽, № {id} — {URL}». Сортировка применяется.
- `<equal_multiplicity>` — не было повода проверить сегодня (на одинаковых лотах не тестировали), но регрессий не видно.
- `<refinement_dialogue>` — частично работает. Бот задаёт уточняющий вопрос на запросах вроде «однокомнатные любой ЖК», но иногда сразу выдаёт результат (тоже допустимо).
- `<dates_policy>` — не тестировали сегодня, оставить как было.
- `<domain_rules>` — терминология «корпус N = N-я очередь» работает; в R3.1 ответ содержал «корпус 1 секция 2», «корпус 1 секция 6».

## 2. Требуют доработки на Flynn (отличия от b24u)

### `<no_exact_match>` — «лесенка погрешности» не помечает превышение

**Что сломано:** В R3.2 «до 30 млн самую классную» бот выдал 23.25 млн (в бюджете) + 32.79 млн **без пометки** «±10%, чуть выше». На b24u в v6.1.3 пометка была.

**Что положить в Flynn-промпт (адаптировано):**
```
<no_exact_match>
Точного совпадения нет → ищи близкие по «лесенке погрешности»:
  ±3% → ±5% → ±10% от запрошенной цены/площади.
Когда выдаёшь варианты вне точного бюджета, КАЖДЫЙ помечай:
  «в бюджете», «±5%», «±10% — небольшое превышение», «выше бюджета».
Уйти в "не нашёл" — только если в радиусе ±10% пусто.
</no_exact_match>
```

### `<ambiguous_query>` — не должен давать дорогу к fallback

**Что сломано:** C2 «сколько двушек Моисеенко 10 с чистовой отделкой» → дефолт «оставьте контакт». На самом деле двушки с отделкой есть, что подтверждено тем же запросом без «сколько».

**Что положить в Flynn-промпт:**
```
<ambiguous_query>
Запрос с фильтром-уточнением (отделка, корпус, бюджет) + "сколько / количество / как много":
- НЕ уходи в дефолт "оставьте контакт".
- Не называй число (всегда возможен недосчёт по Top-N).
- Покажи 2-3 примера, что есть в базе по фильтру, + slice-URL каталога с тем же фильтром.

Если по фильтру в RAG 0 карточек ВСЕХ типов — только тогда дефолт-сообщение.
</ambiguous_query>
```

### `<count_query>` (новый блок) — обходит ограничение Top-N

**Контекст:** RAG возвращает 8–15 карточек из ~263 в фиде. Бот считает то, что видит, и врёт. На b24u в v6.1.4 правило «не называй число» подняло точность с 1/7 до 6/7.

```
<count_query>
На вопросы "сколько / количество / как много":
- Точное число НЕ называй (видишь только Top-N).
- Дай 2-3 примера-лота из выдачи + диапазон цен/м².
- Обязательно: slice-URL каталога с тем же фильтром, чтобы агент увидел полный список на портале.
- Допустимо: "точное количество не фиксирую, по фильтру в каталоге N лотов" (если N виден в карточке-срезе).
</count_query>
```

### `<source_routing>` (новый блок) — приоритет фид > KB при конкретике

**Контекст:** Бот может процитировать KB-карточку (например, «студия 41.79 м² Talento»), хотя в фиде есть та же квартира с актуальным URL. Сейчас Flynn делает это правильно, но правило стоит зафиксировать.

```
<source_routing>
Для конкретных лотов (запрос содержит площадь/этаж/номер/цену):
- Сначала ищи в <OFFER> (фид) — там актуальные URL booking.fizika.group/flat/<id>/.
- KB-карточки используй только для:
  * описания ЖК в целом
  * условий продаж / документов
  * slice-каталогов с готовыми фильтр-URL
- Если в фиде есть лот с теми же параметрами, что и в KB-карточке, ВСЕГДА цитируй фид-URL.
</source_routing>
```
