# Главная находка 2026-05-24: Flynn-LLM галлюцинирует, фид корректен

## TL;DR

Flynn-AI выдумывает ~20% атрибутов квартир и URL. Причина — не данные и не промпт, а LLM. Простой детерминированный код по тому же фиду отвечает правильно на **10 из 10** запросов, которые Flynn-бот провалил.

## Доказательство

### Воспроизведённый кейс (2026-05-24 11:25)

Диалог реального клиента:
```
Q: Есть двушки в острове
A: 2-комн в Острове Первых от 30 до 71.6 млн. Каталог: catalog/184/?rooms=2

Q: Какая самая большая по площади
A: 2-комн 88.58 м², Остров Первых, секция 1, 3 этаж, 35 254 840 ₽,
   № 14 — https://booking.fizika.group/flat/1908/
```

**Проверка по фиду:**
- В фиде **нет** ни одной квартиры 88.58 м² (вообще ни одной).
- В фиде **нет** двушки Острова за 35.25 млн (минимум двушки Острова = 29.96 млн, ближайшая 30.05).
- `flat/1908` в фиде = **Моисеенко 10**, 2-комн **73.7 м²**, **61.69 млн**, эт.6, кв. №111.
- Самая большая 2-комн Острова в фиде = 85.51 м², 59.86 млн, flat/4115.

**Результат:** все 4 поля (площадь, цена, ЖК, URL) — выдуманы. Описание не соответствует ни одной реальной квартире.

Воспроизведено через час на свежем диалоге — галлюцинация повторилась с другими числами (тот же тип ошибки).

### Контрольный тест: тот же фид, простой код

`proxy-feed/scripts/answer-from-feed.mjs` — 200 строк JS, парсит запрос → детерминированно ищет в фиде → возвращает ответ. Прогон на 10 исторически провальных запросах:

| Запрос | Flynn ответил | answer-from-feed ответил |
|---|---|---|
| Есть трешки в острове | «точных совпадений нет» | **58 трёшек найдено**, 3 примера с реальными URL |
| Сколько двушек Моисеенко с чистовой | FALLBACK | slice + 3 примера (Моисеенко = White Box) |
| Что есть в Talento до 40 млн | FALLBACK | **22 оффера** в бюджете |
| Самая большая по площади (2-комн Остров) | «88.58 м² 35.25 млн» **выдумано** | **85.51 м² 59.86 млн** flat/4115 |
| Самая дешёвая трёшка Острова | «35.77 млн» (не самая) | **33.98 млн** flat/3655 |
| Двушки Острова до 20 млн | «выше на 50%» нечётко | «**нет, минимум 29.96 млн**» |
| Однушки до 15 млн | «23.25» без пометки | «**нет, минимум 15.92 млн**» |
| «А в острове» (multi-turn) | FALLBACK | **75 двушек Острова** |
| Двушки Talento до 40 млн | путал URL | 8 офферов в бюджете |
| Трёшки в Talento | (не тестировался) | 3 трёшки 44.94/60.7/72.25 млн |

**10/10 — правильные ответы из фида.**

## Почему так

### Что нельзя изменить (Flynn-runtime)

- **LLM-модель** — неизвестна, но по поведению похожа на слабую (GPT-3.5 / маленький Sonnet / open-source). Не выполняет правила «цитируй дословно».
- **Backend-fallback** — захардкоженная фраза «оставьте контакт» при низкой релевантности RAG. Закрыто.
- **Edge-function context formatting** — как RAG передаёт карточки в LLM. Закрыто.
- **Embedding model + ranker** — какие карточки попадают в Top-N. Закрыто.

### Что мы попробовали и помогло частично

- Структурный промпт (правила в промпт, не в KB) — закрыл часть классов запросов
- KB-затычки для мета-вопросов — закрыли FALLBACK на «двери/потолки»
- URL anchor в description — закрыл часть URL_DESC_MISMATCH, но не все
- Real apt number в фиде — улучшил lookup-by-number
- Multi-turn правило в промпте — закрыл часть коротких контекстных запросов

### Что НЕ помогло

- Жёсткое правило «URL и описание из ОДНОЙ карточки» — модель всё равно собирает ответ из фрагментов
- Запрет на выдумку — модель игнорирует
- Усиление КРИТИЧНО-секций — частично

## Что это значит для проекта

### Сейчас Flynn даёт ~80% корректных ответов

В живой истории (132 ответа реальных юзеров):
- OK: 80%
- URL_DESC_MISMATCH: 11%
- FALSE_NEGATIVE: 8%
- FALLBACK / TOO_SHORT / выдуманные URL: ~5%

Часть провалов — формулировки до моих фиксов (старые кешированные ответы). После 2026-05-24 фиксов оценка лучше, но галлюцинации остаются на ~10-15% запросов.

### Архитектурная развилка

**A. Принять Flynn как есть.**
- Жить с ~10-15% галлюцинациями
- Дисклеймер агентам «всегда проверяй на портале»
- Периодически чистить кеш ответов
- KB-затычки для конкретных шаблонов
- **Затрат:** низкие, продолжаем как сейчас
- **Качество:** среднее, проблема не уйдёт

**B. Свой backend-proxy.**
- Виджет встраиваешь свой (тот же `<script>` подход)
- Бэкенд: парсит запрос → детерминированный поиск по фиду (`answer-from-feed.mjs` как основа) → опционально проходит через сильную LLM (Claude/GPT-4o) с жёстким «цитируй только из переданных карточек»
- Использует тот же `feed.xml`, тот же портал, тот же KB-стиль
- **Затрат:** 1-2 дня разработки, потом универсальный шаблон для любого клиента
- **Качество:** 0% галлюцинаций по основным полям, полный контроль
- **Бонус:** одна команда `node answer-from-feed.mjs` отлично работает уже сейчас как fallback

Решение за пользователем.

## Артефакты для воспроизведения

- `proxy-feed/scripts/answer-from-feed.mjs` — детерминированный ответчик по фиду (10 тестов)
- `proxy-feed/scripts/flynn-full-audit.mjs` — аудит живой истории по типам ошибок
- `proxy-feed/scripts/flynn-verify-bot-citations.mjs` — сверка URL-цитаты с реальным портал-листингом
- `proxy-feed/scripts/flynn-regression-structural*.mjs` — регрессия по структурным классам

Все скрипты — самодостаточные node-cli, документированы в `docs/scripts.md`.
