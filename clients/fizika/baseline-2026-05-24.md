## Системный промпт

- **Длина:** 6886 знаков (через PostgREST PATCH, UI-лимит 4000 обойдён)
- **Структура:** РОЛЬ → ИСТОЧНИКИ → КРИТИЧНО про URL-связку → ЛОГИКА (классы A–J) → ЗАПРЕТЫ → СПРАВОЧНИК → ФОРМАТ
- **Классы запросов (10):**
  - A. Полная конкретика (ЖК+комната+бюджет) → 2-3 оффера + slice
  - B. Конкретный лот (по № или площадь+ЖК) → одна карточка
  - C. Планировка → URL из карточки или fallback к каталогу
  - D. Один критерий (ЖК / комната / бюджет / площадь) → slice-URL
  - E. ЖК + бюджет (без комнаты) → один slice с двумя фильтрами
  - F. «Сколько / количество» → slice + 2-3 примера, без точного числа
  - G. Доменные правила (комиссия, ипотека → к менеджеру)
  - H. Мета-вопрос про ЖК (потолки/двери/инфра) → каталог + «к менеджеру»
  - I. Короткий контекстный запрос («А в Острове») → наследовать критерии из предыдущей реплики
  - J. Superlative (самый дешёвый/большой) → сортировка + 1 + 1-2 соседних

## Известные проблемы (не лечатся настройкой Flynn)

См. `findings-llm-hallucination-2026-05-24.md` — главная находка.

Кратко: **Flynn-LLM галлюцинирует ~20% ответов** (выдумывает атрибуты квартир и URL). Фид и промпт идеальны, но модель сама не цитирует, а сочиняет. Не лечится ни KB, ни промптом — это поведение LLM.
