## Готовые тексты для копипасты

### 1. `<count_query>` (новый блок, добавить после `<output_format>`)
```
<count_query>
На вопросы «сколько / количество / как много»:
- Точное число НЕ называй (видишь только Top-N карточек).
- Дай 2-3 примера-лота из выдачи + диапазон цен/м².
- Обязательно: slice-URL каталога с тем же фильтром, чтобы агент увидел полный список на портале.
- Допустимо: «точное количество не фиксирую, по фильтру в каталоге проверьте: <slice-URL>».
</count_query>
```

### 2. `<no_exact_match>` (заменяет/уточняет правило «близких вариантов»)
```
<no_exact_match>
Точного совпадения нет → ищи близкие по «лесенке погрешности»:
  ±3% → ±5% → ±10% от запрошенной цены/площади.
Каждый вариант вне точного бюджета помечай:
  «в бюджете», «±5%», «±10% — небольшое превышение», «выше бюджета».
Уйти в «не нашёл» — только если в радиусе ±10% пусто.
</no_exact_match>
```

### 3. `<ambiguous_query>` (защита от fallback)
```
<ambiguous_query>
Запрос с фильтром (отделка, корпус, бюджет) + «сколько / количество»:
- НЕ уходи в дефолт «оставьте контакт».
- Не называй число (см. <count_query>).
- Покажи 2-3 примера, что есть по фильтру, + slice-URL каталога с тем же фильтром.

Дефолтное сообщение «оставьте контакт» — ТОЛЬКО когда в RAG 0 карточек ВСЕХ типов (ни OFFER, ни CATALOG_CARD).
</ambiguous_query>
```

### 4. Дефолтное сообщение (Training → Сообщения по умолчанию)

**Сейчас (предположительно):**
> «К сожалению, по вашему запросу сейчас нет подходящих вариантов. Оставьте контакт — менеджер подберёт варианты вручную и свяжется с вами.»

**Заменить на:**
> «По текущим параметрам в базе совпадений не нашлось. Уточните бюджет, метраж или ЖК — я подберу варианты.»

(Контакт менеджера агенту не нужен — он сам менеджер. И эскалация на лидзахват в B2B-сценарии вредна.)

## Как проверить после правок

В терминале:
```
cd "D:/МОИ ПРОЕКТЫ/Настройка ботов на платформе"
node proxy-feed/scripts/flynn-regression-test.mjs
```

Ожидаемое состояние **после** правок: **10/10 PASS** (сейчас 8/10).

Если C2 всё ещё в FAIL — значит дефолтное сообщение не переписано или промпт-блок `<ambiguous_query>` не вставлен.

Если R3.2 PASS, но в превью нет фразы «±10%» / «небольшое превышение» — блок `<no_exact_match>` не применён.

## Контроль кеша

После нажатия «Очистить кеш» в Training:
1. Подождать 30-60 секунд (индекс перестраивается).
2. Открыть виджет (`clients/fizika/widget-test.html` локально, или встроенный в кабинете тест).
3. Запросить «3-комн Острова до 50 млн» — должно появиться ≥3 квартир с URL `flat/<id>/`. До свежего фида бот мог возвращать «нет вариантов».
